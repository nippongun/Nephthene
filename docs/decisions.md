# Decisions

| Date | Decision | Why | Alternatives rejected |
|---|---|---|---|
| 2026-10-21 | Ground fog is its own full-screen pass (shaders/fog.wesl), not Bevy's `VolumetricFog` / `FogVolume`. | Bevy 0.20's volumetric fog gives no sunlight to samples outside the directional shadow cascades (the example's end at 250 m, so km-away valley fog would be ambient only), its ambient term ignores the density texture (`exp(-L*sigma) * ambient` over the whole box), and it does not read the cloud shadow cookie. Sky light is the dominant light in fog. | Bevy `FogVolume` with a CPU-baked 3D density texture (engine-native, but unlit at range). |
| 2026-10-21 | Fog shape is a 2D baked map (pool top, mist, sunlit altitude, amount) plus an analytic vertical profile, not a 3D froxel/voxel grid. | The physics is 2.5D: a level pool top over the terrain and exponential mist. A 2D map keeps the top and the ground contact sharp at any distance for 256 KB, and the march is clipped to the fog's altitude band. | 3D density texture (vertical resolution limits the flat top and the ground-hugging mist; 4 MB+ re-uploads). |
| 2026-10-21 | Burn-off is per texel and gated by terrain shadow, not by sun elevation alone. | A valley in a mountain's shadow keeps its fog after open ground has cleared; an elevation-only burn clears both at once. Gate G16 with red arm `ground_fog.ignore_shadow`. | One global amount (elevation-only burn). |
| 2026-10-21 | Ground fog is off by default. | AGENTS.md rule 2: the shipped look keeps its old value; the goldens are unchanged. | On by default. |
| 2026-10-21 | Per-pass cost gates (tests/cost.rs) use the roadmap's proposed split: clouds march+resolve 1.2 ms, shadow 0.2, rain shafts 0.3, rain FX 0.3 at 1080p on Metal; Retina reaches the same budgets through `clouds.render_scale` x 1920/2880 (same marched pixels). Gates skip on CPU adapters (`device_type: Cpu`). Red arms multiply the work (div 1 + scale 1; shadow_every 1 + res 2048; scale 1 + 4x shaft steps; 16x rain quads). | The roadmap's budget, owner's call; lavapipe has no meaningful GPU time. Rain FX has no render_scale, so its Retina run is full resolution under the same budget: a failure there means rain needs a scale knob. | A second Retina budget; wall-time A/B on lavapipe. |
| 2026-10-21 | Rain FX cost is the main transparent pass span (rain on minus off), not a dedicated rain pass. | Timing-only change: the rain quads stay ordinary Material draws; the span is bracketed by two empty passes on the view target so the GPU orders them against the transparent pass. | Moving rain into its own timed pass (render change); Bevy's RenderDiagnostics (needs timestamps inside passes, which Metal lacks). |
| 2026-10-21 | Shaft gust immunity is gated in core (unit test `shafts_do_not_lean_with_gusts`, 60 fps over 70 s): foot swing <= 4 m (one pixel at 5 km, 1080p 75 deg); red arm `shafts.gust_lean` (lean follows the live drop lean). The plugin calls the same `shaft_slant_step`. | Pure logic in core with unit tests (AGENTS.md rule 6); a render gate would need a minute-long live sequence for the same claim. Default 0.000 m, red arm 94 m. | Render sequence gate measuring shaft foot motion. |
| 2026-10-21 | Re-added old G1-G4 as G1 sun disc (centroid within a quarter disc of the projected clock sun, diameter +-25% of SunDisk::EARTH; red arm overcast) and G2 MSAA hairline (edge pixels brighter than both sides by > 2 levels <= 1%; red arm `sky.msaa_fix=false`) in tests/sky_gates.rs. The old gate texts were not in the history; these are rebuilt from the claims. | lavapipe: G1 centroid 0.1 px off, 29.9 vs 28.8 px, overcast 0 px; G2 0.000 vs 0.077. | |
| 2026-10-21 | Panel pointer self-test (`--panel-test`) deferred until Phase 0 merges (owner). | It needs src/panel.rs, Phase 0's file. | |
| 2026-10-21 | Golden pack = reference renderer (`clouds.update_div` 1, settle 300) with each still the mean of 64 frames; sway frames unmeaned. The update run re-renders each still 7 frames later and requires the phase diff <= half the bound (the rest is the driver/compiler allowance). Bound rule unchanged (half the 20% light-gain score). | The div-4 still is still converging at any practical settle, so a single-frame pack measured frame phase, not look. The div-4 resolve's look is gated against the same div-1 reference by G7-G14. The phase check is a pack sanity check, not a gate: it has no config red arm (the old method would read ~0.07 for a 7-frame shift, under half the bound). `NEPHTHENE_GOLDEN_DIR` / `NEPHTHENE_GOLDEN_CASES` let a pack be made elsewhere without touching tests/golden/. | Widening the bound; regenerating the old single-frame pack; a longer div-4 settle (0.10 per 16 frames at 600). |
| 2026-10-21 | Rain and storm scene checks (tests/scenes.rs) ship red: they measure sky rows above the horizon; budgets 1% (rain) and 5% (storm) are not lowered to pass. Storm red arm `storms.sky_scale` 0.1 (authored intensity is not rendered). | They document open bugs (rain near-invisible at full intensity, storm cells render as horizon lenses); the storm red arm separates only once storms render as towers (Phase 2). | Lowering the budgets to the current render. |
| 2026-10-21 | Fog march runs at half resolution (`ground_fog.render_scale` 0.5) into a fog target and a surface-distance target, with a depth-aware full-resolution composite, and reads a baked 64^3 noise texture instead of per-step hashed noise. | Full-resolution hashed noise cost about 30 fps on a Retina Mac (6.4 Mpx x 48 steps x ~70 hashes per step). On the software renderer the half-res pass cut fog cost about 5.5x, with a mean image difference of 0.67 levels vs full res. | Fewer steps (visible banding and grain). |
| 2026-10-21 | Fog march default render_scale 0.25 (was 0.5), f16 hardware-filtered fog map and ground, gather-based composite. | Metal G19 measured 6.57 ms at half res vs a 1.5 ms budget. On lavapipe quarter res cut the march 3.7x vs half with a mean 0.61-level difference from full res, a better trade than halving steps (0.77 levels, 1.7x). | 24 steps at half res (more error, less saving); temporal accumulation first (more plumbing; next if the budget still misses). |
| 2026-10-21 | Ground fog accumulates its march over frames at march resolution (resolve pass, ground_fog.temporal_alpha 0.1) with a same-surface neighbourhood clamp; the composite upsamples the resolved fog. | The per-pixel step jitter was the pool-edge speckle; averaging it over frames costs one cheap low-res pass and lets the march keep its step count. G21 measures frame-to-frame flicker of a still view rather than a spatial median test, which counts the converged ragged top as grain. | Accumulating at full resolution with sub-texel jitter (also removes the 4 px steps; more plumbing, next if the steps show on Metal); more march steps (cost). |
| 2026-10-22 | The weather map advects by translation: `Weather.map_shift` += `map.advect` x the mean wind x game seconds, and every consumer reads map = world + `world_offset_m` - shift (`core::map_xz`). The GPU gets it through the existing `world_offset` uniform. | With one global wind the advection equation's exact solution is a translation: no resampling, no diffusion, no new pass, no shader or uniform-struct change, and the CPU `here` and the clouds read one number. Schneider 2022 scrolls the cloud field the same way. | A ping-pong GPU advection pass with a CPU read-back (needed once the wind is a field, Phase 2 step 2: a non-uniform wind cannot be a translation). |
| 2026-10-22 | Map advection runs on the game clock (frozen when the clock is); the cloud noise drift stays on real time. | Weather systems should cross the map in game hours whatever the time-lapse (storms already run on game time). The noise drift is what the eye reads as wind on screen. Shots stay deterministic: the clock is frozen unless `--live`. | Real time (at the default 15x clock a front would take 15x longer than the day it belongs to). |
| 2026-10-22 | `map.advect` defaults to 0 (the old fixed map); `map.wrap` defaults to false. | AGENTS.md rule 2: the shipped look keeps its old value, and the goldens are unchanged. Schneider 2017 kept the coverage fixed on purpose for art-directed skies. Wrap needs a tileable map, and the built-in procedural one is not. | advect 1 on by default (owner's call). |
| 2026-10-22 | `map.wrap` repeats the map on the CPU read and the GPU sampler, and keeps the shift within one period. `clouds.background` with wrap is refused at start. | Without wrap an advected map runs out of weather. Frostbite repeats its weather texture over the world (Hillaire 2016). Both reads must wrap the same way, or rain and clouds part at the seam. | Clamp only (the edge texels smear across the sky after a few game hours). |
| 2026-10-22 | `map.start_shift_m` is the map's initial state, like `clock.start_hour`. | A saved game restores where the weather had got to. The G22 render gate needs a deterministic shift without running the clock. | Setting `Weather.map_shift` only from host code (fine for hosts, but out of reach of `--set` and so of the shot gates). |
| 2026-10-22 | Storm genesis keeps sampling the unshifted map. | The shift is integrated state, not a function of storm time. Births are re-derived at every timetable rebuild, so sampling a moving map would make live storms appear or vanish at rebuilds. Phase 3 paints storms into the map as fields, and then they advect with it. | Sampling the shifted map at rebuild time (pops). |
| 2026-10-22 | Lightning: the schedule runs on storm time, a flash plays out on real time. A flash found between last frame's and this frame's storm time starts now and its strokes, light and thunder delay count real seconds. | At the default time-lapse a flash's 0.3 s of strokes would last milliseconds of real time, and thunder 8 km away would arrive in a fraction of a second; the player sees and hears real seconds. A storm-clock step longer than `storms.lightning.jump_s` (start, a panel clock change) fires nothing, rather than every flash in the skipped span at once. | Everything on storm time (flashes invisible at time-lapse); everything on real time (the schedule would no longer follow the storm's lifecycle). |
| 2026-10-22 | `storms.lightning.enabled` defaults to false. | AGENTS.md rule 2: with storms on, the shipped look keeps its old value (no flashes); storms themselves are off by default too. | On by default with storms (owner's call). |
| 2026-10-22 | The channel is a camera-facing ribbon at least `min_px` pixels wide whose radiance is scaled by width / drawn width, added over the scene (premultiplied, alpha 0) and dimmed by the camera's own `DistanceFog` (Atmospheric extinction). | A 3 m channel is a tenth of a pixel at 8 km: drawn at its true width it breaks into dots (G23 red arm 0.03 vs 0.23 of the rows). Scaling by the width ratio keeps the light it sends independent of distance. Reading the camera's fog keeps the channel and the scene fading alike without a second fog model. | True-width lines (dots at range); a bloom-only glow (Bevy's bloom is a host camera choice). |
| 2026-10-22 | Flash light: one Bevy `PointLight` per live flash (pool of `max_live`, no shadows), placed along the channel at `light_at`. | Engine-native, lights every PBR surface the host has; one or two lights cost little in clustered forward. | Ambient bump (lights shadowed and unshadowed surfaces alike and cannot fall off with distance); a custom full-screen pass. |
| 2026-10-22 | Two reference GPUs: **A** Apple Silicon / Metal (the owner's review machine, tightest budget) and **B** NVIDIA RTX 5070 Ti / Vulkan (the headroom tier). `tests/golden/` gains a pack per renderer, selected by the detected adapter. | One reference GPU cannot carry both a "fits a tight budget" claim and a "uses a big GPU well" claim; and the Apple-only pack is why `cargo test --release` is red in every cloud session (docs/bugs.md). A per-renderer pack closes that bug properly instead of skipping the gate. | A single reference GPU with a scale factor (lavapipe already shows a relative proxy says nothing about absolute cost); widening the golden bound to cover both. |
| 2026-10-22 | The cost budget is a **time wall per quality tier** (`low` 1.2 ms @ 1080p, `medium` 3.0 @ 1080p, `high` 3.5 @ 1440p, `ultra` 6.0 @ 2160p), not one absolute number. A bigger GPU buys a higher tier at the same wall. Per-pass split is a percentage of the wall, so a new pass takes a share rather than adding one. | The old single 3 ms budget could not express "runs on a handheld" and "uses a 5070 Ti" at once, and every new phase was pushing the fixed split over (3.05 ms mean / 3.45 ms on flash frames with nothing from Phases 2-6 in it). Tier walls make the quality knobs the answer to cost, which is also what the host wants to expose as a setting. | A single budget with per-feature on/off cost accounting; separate budgets per resolution (Retina already shows `render_scale` is the right lever, not a second number). |
| 2026-10-22 | "Rival a AAA weather system to 80%" is kept as a 25-row scoreboard in the roadmap with a stated bar (20 rows at `have`, each with a red-armed gate green on both reference GPUs, plus the owner's eye). | The percentage is not measurable as stated, and an unmeasurable target cannot be gated, planned against, or picked up by an executor. A denominator with per-row gates is: it says what is missing (today 7 `have`, 5 `partial`, 13 `none`), and an agent can read it and choose work. The 25 rows and the 80% are arbitrary; the gates on each row are not. | Treating it as a vibe and judging by renders alone; a feature count with no gate requirement. |
| 2026-10-22 | jiaozi158/UnityVolumetricCloudsURP (MIT) is read as a **reference only**; no code is copied from it. | It is a port of Unity's HDRP volumetric clouds, so the MIT badge on the port does not settle the licence on the implementation it derives from, and it is HLSL/URP-shaped so nothing transfers mechanically to WGSL/Bevy. Its value is the property surface a shipped system exposes: it independently confirms this repo's weather-field channel layout (coverage / rain / type), and it argues for two things we lack - a named cloud **preset** library (Phase 1, C1) and a cheap **distant cloud layer** instead of marching all 90 km (Phase 1, scoreboard row 4). | Porting its shaders (licence risk, wrong shader language, and HDRP's model is already available first-hand from Schneider's SIGGRAPH courses, which the repo already cites). |
| 2026-10-22 | Surface temperature is a force-restore model integrated on the game clock, not a fixed diurnal curve. | Weather changes over hours (a cloud deck arriving at midnight stops the cooling); a diagnostic curve would jump with the cover; same spin-up pattern as the fog. | Parton & Logan 1981 diagnostic curve from daily min/max. |
| 2026-10-22 | Fog formation defaults to the air's dew point spread; the old private cooling is the red arm `ground_fog.private_cooling`. | The roadmap's Phase 2 goal (fog reads the shared air); ground fog is off by default, so the shipped look and the goldens do not change; the fog unit tests keep their assertions. | Keep the old cooling by default (two models of the same night). |
| 2026-10-22 | The season's mean temperature is config (`mean_c`, `season_c`, `lag_days`); latitude flips the season and sets the sun. | A fitted zonal climatology would be a magic curve; the host knows its region. | Derive mean and swing from latitude. |
| 2026-10-22 | Orographic precipitation is a second field, separate from the weather field. The weather field moves with the wind; the orographic field stays fixed to the terrain (world frame). The sampler combines them where they are read. | The owner chose this (roadmap question 2). Orographic rain is caused by the ground, so it must not drift downwind with the weather systems, and one texture cannot be in both frames. | One field that does not advect where terrain forces it (needs a per-texel advection mask and mixes two frames in one texture). |
| 2026-10-22 | The air state is a temperature field from the start (`air::Field`), not one global value plus a lapse rate plus a climate field. It is a grid over the weather map's extent in the map's frame, so it moves with the weather (`map_shift`). Each cell runs the force-restore model under its own cloud cover. A cell stores its temperature reduced to `ref_alt_m`; altitude enters where the field is read, through the lapse rate and the `Ground` height there. Vertically it is one linear lapse rate. | The owner chose this (roadmap question 4). A field lets cold and warm air masses move and differ across the map. Storing the reduced temperature means air carried over a ridge reads colder on the ridge and warmer in the valley, instead of carrying the valley floor's temperature up the slope. The climate field (next) sets each cell's restore target. | A 3D grid (a vertical profile is only needed for inversions; a sounding per cell is the upgrade); storing the temperature at the cell's ground (wrong once the map moves over relief); one global value plus a lapse rate (owner). |
| 2026-10-22 | Precipitation type `precip_kind` (0 rain, 1 snow, sleet between) is a smoothstep of the air temperature at the ground from `air.rain_c` down to `air.snow_c` (defaults 2.5 and -0.5 C, untuned). | Jennings et al. 2018 (Nature Communications 9:1148): the air temperature at which rain and snow are equally likely ranges from -0.4 to 2.4 C over Northern Hemisphere land, mean 1.0 C. A blend (not a switch) lets a front turn rain to snow over minutes. Reading temperature, not the freezing level, keeps it finite without a lapse rate. Hail is convective and comes with the storm fields (Phase 3). | A switch at the snow line (pops); an altitude band below the freezing level (infinite without a lapse rate). |
| 2026-10-22 | The climate field is a second RGBA8 map in the weather map's format, fixed to the world: R mean temperature offset and G humidity (signed, byte 128 is neutral), B ground snow and A ground wetness (0..1). Without a map, every place is `climate.uniform`. | This is the roadmap's channel list. One format means one loader and one bilinear read. Signed channels with 128 as neutral keep an unpainted map exactly neutral. The climate belongs to the ground, so it is not shifted by `map.advect`. `uniform` lets a shot try a desert or a tundra with `--set` and no image. | A palette of climate classes (bilinear reads of an index are meaningless at class borders); 0..255 linear ranges (no exact neutral byte). |
| 2026-10-22 | The climate localises the air config per place (`climate::air`) instead of adding terms to the model: the place's restore target is `mean_c + offset`, its air mass dew point depression goes toward `dry_dew_below_c` or `wet_dew_below_c`, and its sun heating is scaled by the share of sunlight absorbed over snow compared with bare ground. Ground wetness is the wetter of the rain's and the climate's. | One code path: the field's cells, the plugin's readout and the fog's spin-ups all run the same single-place model with a localised config, so a neutral climate is exactly the old model (gated to 1e-4 K). Ranges come from observed climates (docs/climate.md: Phoenix, Singapore, Yakutsk, Dallol, albedo tables). | New per-place terms in `air::rate` (two code paths to keep equal); scaling the diurnal range directly (the model already makes it from heating and cover). |
| 2026-10-22 | The season's swing (`air.season_c`) stays global; continentality is not a climate channel yet. | RGBA8 is full with the roadmap's four channels, and the swing matters only on yearly timescales. A second climate image (swing, biome) is the upgrade. | Dropping ground wetness to make room. |
| 2026-10-22 | Every feature is on by default (owner): storms, lightning, ground fog, rain shafts (`clouds.shaft_scale` 1), map advection (`map.advect` 1) with `map.wrap`. Supersedes the "off by default" rows for ground fog and lightning and the `map.advect` 0 default. | The owner wants the shipped look to be the full weather system; rule 2's "keep the old value" yields to an explicit owner call. Goldens must be regenerated on the reference Mac. | Off by default (the old rule-2 reading). |
| 2026-10-22 | "Storms form occasionally" is a budget, gated in `crates/nephthene_core/tests/storm_climate.rs`: over 60 game days at the defaults with the camera at the map origin, a mature storm within 40 km for 15-40% of 12-20 h, and storm rain at the camera every 1-5 game days. `storms.rate_per_km2_hr` 4e-5 -> 1e-3 meets it (0.242, every 1.88 days); red arms on both sides (4e-5: 0.014 and none; 3e-3: 0.614 and every 0.75 days). | The owner's word, made measurable; at the old rate a storm was in view 1.4% of afternoons and never rained on the camera in 60 days. One knob changed; genesis and lifecycle unchanged. | Raising `genesis_floor` (changes where storms form, not how often); a per-day schedule (not a field). |
| 2026-10-22 | Storms reach the camera through one pure function, `storm_fx::local` (rain curtain, cover from the column optical depth, gust-front outflow, sky light under the column), read one frame late from `Weather.storm`: `here` takes the wetter and cloudier of the map and the storms, the rain falls with the gust front, the ambient and the atmosphere environment light are dimmed. The sun needs nothing: the cloud-shadow cookie already includes the storm cells. `storms.couple` false is the red arm. | Everything that reads `here` (rain, fog formation, audio, panel) follows the storm with no new paths; the one-frame lag is far inside `sim.here_tau_s` (5 s smoothing). | Writing `here` from storms.rs after the tick (the next tick's smoothing would fight it); a storm-local field per consumer. |
| 2026-10-22 | The built-in map tiles: the coverage swell is sin(2 pi cycles u + phase) per axis with whole `map.default_cycles` [1, 1] (were 7.1 and 5.3 rad, 1.13 and 0.84 cycles), texel centres at i / n, the rain blob's distance wraps; gate `built_in_map_tiles` (seam step 5 vs inner 5 levels; red arm the old cycles 44 vs 6). | `map.wrap` (needed so an advected map never runs out) needs a tileable map. The placeholder literals became `map.default_cycles`, `default_phase`, `default_blob`. | Keep the old map and hold edge texels (the weather freezes ~4.6 game hours in at 6 m/s). |
| 2026-10-22 | Orographic slice 1 runs on the CPU only: a baked tile (`orographic::Tile`, fixed to the terrain) is folded into `Weather.here` (rain, fog, panel). It is off by default (`orographic.enabled`). The cloud shader reads it in slice 2. | The owner chose two fields combined at sample time. The CPU half can be gated in core (windward vs lee) without a GPU check. Off by default because until the shader reads the tile, its cover would make rain fall from sky the clouds draw as clear. | Shader and CPU in one PR (a new texture and uniform across three passes, and a GPU check before anything is gated). |
| 2026-10-22 | The orographic and weather fields combine as: precipitation is the larger of the two, cover is the map's plus `cover_weight` times the orographic cover, clamped to 1. | Owner agreed (roadmap proposal). The larger value keeps a frontal rain from being doubled where it crosses a ridge; uplift cloud adds to whatever cloud is already there. | A sum for precipitation (double counting); a max for cover (a cap cloud would vanish under any map cover above it). |
| 2026-10-22 | The uplift sensitivity Cw is computed from the air at the camera (Smith & Barstad 2004: Cw = rho_s Gamma_m / gamma: saturation vapour density times the moist adiabatic lapse rate over the environmental one), scaled by `orographic.gain`. tau_c = tau_f = 1000 s, N_m 0.005 1/s, H_w 2500 m (the paper's example). Precipitation in mm/h maps to the map's 0..1 by `full_mm_h` 7.6 (the AMS line between moderate and heavy rain), and the cloud source rate maps to cover the same way. | Phase 2 reads one air state: warm air rains more over the same ridge. A 10 C, 10 m/s westerly over a 1 km ridge (sigma 3 km) gives light-to-moderate rain: 1.5 mm/h 3 km before the crest, 3.4-3.5 at and just past it, 1.2 at 4.5 km past it, and 0 at 6 km on either side (scratch prototype). With the paper's 1000 s delays, a ridge this narrow spills most of its rain past the crest (U x (tau_c + tau_f) is about 20 km); the cap cloud stays on the ascent. | A constant Cw (it ignores the air's temperature); the old placeholder taus of 8 s (outside the published 200-2000 s range). |
| 2026-10-22 | Snow and sleet are the rain pass's own streak quads: a quad is a flake when its salted hash (`rain::FLAKE_SALT`) is below `kind` (`rain.kind_force`, else the air's `precip_kind`), so sleet is a mix of drops and flakes and the kind blends with no second particle system. Flakes are camera-facing discs on their own velocity (`snow_fall_mps`, `snow_drift`) with a swirl (`flutter_m`, `flutter_hz`), wrapped in their own narrower window (`snow_half_m`: flakes fall 9x slower, so the same quads hold 9x the density); splashes and wetness take only the liquid share `intensity x (1 - kind)`. | The roadmap's "one particle pass, several kinds"; stateless like the streaks, mirrored in `core::rain` and pinned in `layout_pins`. | A second snow particle system (twice the quads and upkeep); a per-quad kind blend of motion (a flake half-way to a streak reads as neither); sleet as hail-like bouncing pellets (left for a later slice). |
| 2026-10-22 | Flash light on the clouds is integrated in the march like the sun term but kept in its own low-res target (`MarchOut.flash`) that the cloud composite adds on the same frame; it never enters `lum`, the highlight shoulder, the resolve or the history, so a flash cannot smear or be clamped by the 3x3 history clamp. Each flash is a point source scaled from the scene point light's flux (`cloud_flash_scale`: `light_lm x light / (4 pi)^2`) softened by a glow radius; the flashes are a separate uniform (cloud binding 7), not `CloudGpu` fields. | The roadmap's "own unresolved term"; a separate uniform keeps `CloudGpu` stable for the concurrent orographic slice (agreed: it takes bindings 8 and 9). | Re-weighting the history on flash frames (the 3x3 clamp and the 1/16 update still smear); folding the flash into `lum` (shouldered and resolved). |
| 2026-10-22 | Orographic slice 2: the cloud march, shadow and shafts read the tile through `map_sample` (clouds_common.wesl). It is a second RGBA8 texture at cloud bindings 8 and 9 (7 is the flash uniform) (R cover, G precip, clamped, nothing outside the tile), combined like `orographic::combine`, and placed by three uniform fields at the end of `Clouds` (`oro_origin`, `oro_size` with 0 = no tile, `oro_weight`). `orographic.enabled` stays false until the owner checks the look on the GPU (docs/handover.md). | One sampling function feeds every pass, so the clouds, their shadow, the shafts and the CPU weather all see the same terrain share. Appending fields and bindings keeps the other session's flash-light work (its own uniform at the next binding) a clean merge. Off until the owner's look call: the cap cloud is a visual change, and owner decisions set the look (AGENTS.md). | Baking the tile into the weather map texture (the map moves with the wind, the tile must not); a separate cap-cloud pass (a second march). |
| 2026-10-22 | The orographic bake lifts air from the tile's lowest ground, which condenses only above its lifting condensation level: `orographic.lcl_m_per_k` (125 m, Espy) x the dew point spread there. The terrain is clipped at that height before the FFT, and Cw is the base air's. The bake takes the air at `air.ref_alt_m` (temperature and dew point) and lapses it to the base. | Smith & Barstad's linear theory assumes saturated air. With the afternoon air's 9 K spread, every 45 m hill of the test valley raised cloud and the whole sky went overcast (the first G31 run: the lee half changed more than the windward half). Real air must first be lifted to saturation. This also ties the cap cloud to the air state: humid air clouds the hills, dry air only the high ridges. | A threshold on the output cover (it ignores how high the air must rise); a larger `full_mm_h` (it hides the hills and the ridge alike). |
